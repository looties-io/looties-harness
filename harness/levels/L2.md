# Level L2

Summary of [the levels](../../docs/agent-harness.md#difficulty-levels); the standard wins on conflict.

- Forced for auth, money, migrations, access control and grants, deletion, production operations, wide changes and the harness.
- Announce `Level L2: <reason>`. Investigate first, then give: the goal restated, opening with a one-sentence `Understood:` line (the interpretation ledger reads it), 0 to 3 blocking questions with a default each, numbered falsifiable assumptions, and a plan naming files and rejected alternatives.
- Wait for the maintainer's approval before implementing.
- After approval: commit, push the feature branch, open a draft pull request and mark it ready.
- Never push to the integration or release branch or arm auto-merge. Never merge, except a production command the maintainer confirmed, such as the release merge.
- Production commands ask every time. A user-visible change needs a validated mockup first.
